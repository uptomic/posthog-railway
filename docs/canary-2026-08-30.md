## Result

The isolated local canary started successfully on fresh PostgreSQL, ClickHouse, Kafka/Redpanda,
Redis, and object-storage volumes.

- Embedded Web revision matched the candidate commit exactly.
- Django reported zero pending migrations after startup.
- ClickHouse recorded 315 migrations through `0309_metrics_kafka_ingest` and reported that its
  migrations were up to date.
- `GET /_health` returned HTTP 200 with body `ok`.
- Unauthenticated `GET /api/` returned HTTP 401, confirming that the application route was live and
  protected.
- The Web container remained running after the migration and server-start sequence.

The first boot exposed the expected dependency ordering: ClickHouse migrations could not run until
Django had created its metadata tables. After Django completed, the coordinated second startup
applied all ClickHouse migrations and reached readiness. Production must preserve this migration
order.

## Remaining production gate

This canary proves clean installation and startup only. It does not prove that the January 2026
production PostgreSQL and ClickHouse data can be migrated safely to this candidate. Before
production promotion, restore representative production data into an isolated environment and run
the full authenticated, ingestion, query, feature-flag, replay, MCP, and Pulse checks from the
promotion runbook.
